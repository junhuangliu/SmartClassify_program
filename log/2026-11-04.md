## [16:41:15] 修复 USART1 乱码：HSE 晶振由 25MHz 更正为 8MHz

- **目的**: 串口能收到数据但为乱码，定位为系统时钟与晶振不匹配导致波特率错误
- **涉及文件**: Core/Inc/stm32f4xx_hal_conf.h, Core/Src/main.c, core_code.ioc, Core/Src/freertos.c
- **改动摘要**:
  - 根因：.ioc/HAL 假设 HSE=25MHz（PLLM=15/PLLN=144），但正点原子 F407(STM32F407ZGT6) 板载晶振为 8MHz；实际 SYSCLK 仅 38.4MHz，HAL 仍按 120MHz 计算 BRR，实际波特率约 36864，导致乱码
  - `stm32f4xx_hal_conf.h`: HSE_VALUE 25000000 → 8000000
  - `main.c` SystemClock_Config: PLLM 15→8、PLLN 144→240，SYSCLK 仍为 120MHz、APB2 60MHz（保持 WS2812/SPI 时序不变）
  - `.ioc`: 同步 RCC.HSE_VALUE、RCC.PLLM、RCC.PLLN、RCC.VCOInputFreq_Value
  - `freertos.c`: Uart1RxTask 空闲 1s 发送 "UART1 tick" 心跳，方便确认串口在线

- **结果**: 完成（待上板确认 115200 是否正常）
- **备注**: 若实际晶振并非 8MHz，需改回对应 HSE 与 PLL；建议后续在 CubeMX 中确认 Clock Configuration 后再生成，避免手改 .ioc 与图形配置不一致

## [16:47:43] 修复 USART1 回显叠加：循环 DMA 的 Size 为累计值

- **目的**: 串口回显出现“叠加”（后一条包含前一条内容），改为每条消息只回显本次新增数据
- **涉及文件**: Core/Inc/uart1_comm.h, Core/Src/uart1_comm.c, Core/Src/freertos.c, Core/Src/stm32f4xx_hal_msp.c, core_code.ioc
- **改动摘要**:
  - 根因：`HAL_UARTEx_ReceiveToIdle_DMA` 配合**循环 DMA** 时，空闲事件回调的 `Size = RxXferSize - DMA剩余计数` 表示“本轮 DMA 周期内累计字节数”，并非本次新增长度；DMA 缓冲未满 256 字节时会不断累积，导致回显叠加
  - `stm32f4xx_hal_msp.c` / `.ioc`: USART1_RX 的 DMA 模式由 `DMA_CIRCULAR` 改为 `DMA_NORMAL`
  - `uart1_comm.h`: `Uart1RxMsg_t` 由“指针+长度”改为“长度 + 内联数据[256]”，避免共享 DMA 缓冲被覆写
  - `uart1_comm.c`: 空闲回调中把本次数据 `memcpy` 进消息体入队，随后重新调用 `HAL_UARTEx_ReceiveToIdle_DMA` 开启下一次接收（普通模式必须手动重启），Size 即为本次实际长度
  - `freertos.c`: 回显改用 `msg.data`
- **验证**: 在 Code_set_Folder/core_code 执行 make -j4 编译通过（text 25476 / data 16 / bss 24240）
- **结果**: 完成（待上板确认回显不叠加）
- **备注**: 队列元素增大到 258 字节 × 16，占用约 4.1KB 堆，当前 configTOTAL_HEAP_SIZE=15360 可容纳；流水灯“变快”是时钟修正后的正常表现（此前 osDelay 实际慢约 3.1 倍），如需恢复旧观感可等比放大 WS2812Task 的延时
